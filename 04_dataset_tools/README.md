# 04 · 训练数据制作工具

为 [`02_vision_maixcam/`](../02_vision_maixcam/) 的 YOLO26 钢珠检测模型准备训练数据。

**本仓库只包含脚本，不包含图片数据。** 标注帧与原始视频体积过大（约 90MB），
请用下面的脚本自行生成，或联系作者获取。

---

## 文件说明

| 文件 | 作用 |
| :--- | :--- |
| [`video_to_frames.py`](video_to_frames.py) | 把视频按固定间隔抽帧保存为图片 |

---

## 抽帧脚本

```bash
# 基本用法：每帧都保存
python video_to_frames.py raw/2.mp4

# 指定输出目录、每 5 帧保存一张、输出 png
python video_to_frames.py raw/2.mp4 -o ./2_frames -i 5 -f png

# 同时缩放到 640x480
python video_to_frames.py raw/2.mp4 --size 640 480
```

| 参数 | 默认 | 说明 |
| :--- | :--- | :--- |
| `video` | — | 输入视频路径 |
| `-o, --output` | 视频同目录 `<名字>_frames/` | 输出目录 |
| `-i, --interval` | `1` | 每多少帧保存一张 |
| `-f, --format` | `jpg` | `jpg` / `jpeg` / `png` |
| `--size W H` | 保持原分辨率 | 输出分辨率，**必须同时给出宽高** |

依赖：`opencv-python`。

> ⚠ **注意文件命名**：脚本输出的 `frame_%06d` 是**保存序号**（第几张图），
> 不是原视频帧号。当 `-i > 1` 时两者会显著不同——例如 `-i 2` 时
> `frame_000002.jpg` 对应原视频第 4 帧。若需要回溯到具体时刻，
> 请自行乘上 `interval`，或改用原视频帧号命名。

## 标注数据格式

标注文件为 **X-AnyLabeling / Labelme 兼容格式**——每张图配一个同名 `.json`：

```json
{
  "version": "4.0.0-beta.13",
  "flags": {},
  "shapes": [],
  "imagePath": "frame_000400.jpg",
  "imageHeight": 480,
  "imageWidth": 640,
  "imageData": null,
  "description": ""
}
```

- 有目标的帧：`shapes` 数组里是 `{"label": "ball", ...}`（单类检测）
- 无目标的帧：`shapes` 为空数组——**这些是刻意保留的负样本**，
  用于压制反光点、螺丝等圆形干扰物的误检，不要删除。

## 完整训练流程

1. **采集**：用 MaixCAM 实地拍摄钢珠在摆杆上滚动的视频。尽量覆盖：
   不同光照（顺光/逆光/灯光反光）、不同背景、钢珠在摆杆两端与中间、
   快速运动造成的运动模糊。**赛场光照条件与你实验室不同，这是最容易被低估的一步。**
2. **抽帧**：`video_to_frames.py`。间隔取 `2` 左右通常足够，
   太快会产生大量近乎重复的帧，反而让数据集偏斜。
3. **标注**：X-AnyLabeling，单类 `ball`。**务必包含足够的负样本帧**
   （空 `shapes`），否则模型会在反光点上误检。
4. **训练**：YOLO26 单类训练。可适当降低输入分辨率换取 NPU 上的帧率。
5. **转换**：导出为 AX 系列 NPU 的 `.axmodel`（NPU / VNPU 两个版本）。
6. **部署**：连同 `.mud` 描述文件放进
   `02_vision_maixcam/models/<name>/`，更新 `main.py` 里的 `*_MODEL_PATH`，
   **并重新标定** `AXIS_START_PX` / `AXIS_END_PX` / `AXIS_START_CM` / `AXIS_END_CM`。

> 换模型分辨率是最容易踩的坑：`main.py` 里 `AXIS_*_PX` 的像素坐标是在
> **模型输入图**上量的，不是原始相机分辨率。改了输入尺寸而没重新标定，
> 厘米换算会整体偏掉。
